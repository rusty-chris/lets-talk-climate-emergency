## Context
DESIGN §2.4. Productionise the #2 spike across all MVP sources (Tier A + gated Tier B, §2.1/2.3): NCA5 chapters, NASA/NOAA/Met Office explainers, C3S ESOTC, Hansen 2023+2025, OWID explainers, UNEP EGR, Carbon Brief (verbatim chunks), gate-passed reviews.

## Scope
- Per-source fetchers keyed off the manifest (#5); HTML parsing direct, PDFs via Docling with PyMuPDF fallback, handling the failure modes recorded by #2.
- Structure-aware chunker (section-bounded, ≤~500 tokens, context headers); IPCC curated headline statements (if the feature flag is enabled by #23's legal check): one statement = one chunk, capped ≤10 per SPM.
- Citation metadata per chunk per DESIGN §2.4 schema, incl. `confidence_markers` regex extraction and `consensus_position` propagation (Hansen papers → `beyond-assessed-range`).
- Emit custom-content citation blocks, one per citable unit.
- **Launch dependency (DESIGN §2.3):** assessed-range statements for sensitivity/committed warming/warming levels present via IPCC curated set or NCA5 equivalents — verify presence with a checked test.

## Acceptance criteria
- `make corpus` ingests every signed-off MVP document end-to-end reproducibly (hash-stable chunk ids).
- Chunk-quality hand-audit checklist completed per source family and committed.
- `test_assessed_range_statements_present` passes against the real MVP corpus.

## TDD plan
The chunker is the most unit-tested module in the repo (IMPLEMENTATION.md §1). All unit tests run against the synthetic fixture corpus from #24 — never real Tier B/C text — plus the failure modes recorded by #2. Order:
1. `test_chunks_never_cross_heading_boundaries` (unit) — no chunk spans two sections of the nested-headings fixture doc.
2. `test_chunk_token_length_at_most_limit` (unit) — every chunk ≤ the configured ~500-token cap.
3. `test_context_header_prepended` (unit) — each chunk opens with its document → section-path header.
4. `test_one_sentence_overlap_between_adjacent_chunks` (unit).
5. `test_table_and_figure_placeholders_retained_with_captions` (unit) — one test per failure mode recorded in #2's findings note.
6. `test_golden_chunks_stable_for_fixture_docs` (unit) — full golden-output comparison; golden changes must ship in the same commit with the diff explained (the chunking-experiment scope guard, mechanised).
7. `test_chunk_ids_hash_stable_across_reruns` (unit) — same input → identical ids.
8. `test_confidence_markers_extracted` (unit) — "very likely", "high confidence" captured; `test_negated_qualifier_not_miscaptured` — "not likely" is not recorded as "likely".
9. `test_consensus_position_propagates_to_chunks` (unit) — the beyond-assessed-range fixture doc flags every chunk.
10. `test_headline_statement_is_single_chunk` and `test_headline_statements_capped_at_10_per_spm` (unit) — over the synthetic headline-statements fixture; cap violation fails ingest.
11. `test_citation_blocks_one_per_citable_unit` (unit) — block payloads match chunk count and carry full citation metadata.
12. `test_ingest_fixture_corpus_end_to_end` (integration) — manifest-driven fetch from `file://` fixtures → parse → chunk → blocks; run twice, identical output.
13. `test_assessed_range_statements_present` (integration) — the launch-dependency check: fails when no indexed chunk carries the assessed-range statements for sensitivity / committed warming / warming levels; mechanism verified on the fixture corpus here, enforced against the real corpus at release.
