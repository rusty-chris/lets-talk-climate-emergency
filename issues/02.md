## Context
DESIGN §2.4, §10 Phase 0. Ingestion QA is the schedule long pole; this spike de-risks parsing quality before the pipeline is built.

## Scope
- Parse one NCA5 chapter PDF and one CC-BY review paper with Docling; PyMuPDF fallback wired.
- Implement prototype section chunking: split on headings, ≤~500 tokens, one-sentence overlap, never across headings; prepended context header (document → section title).
- Manually review chunk boundaries on both documents; record failure modes (tables, figures, footnotes, two-column layouts) in a short findings note committed to `reviews/`.

## Acceptance criteria
- Both documents produce chunk lists with correct section paths and no cross-heading bleed, verified by hand and recorded.
- Figure/table placeholders retained with captions as citable text (DESIGN §2.4).
- Findings note names the parsing risks the production pipeline (#7) must handle.

## TDD plan
Spike — TDD applies loosely here (IMPLEMENTATION.md §2 item 6). Do not write tests first; the deliverable is knowledge, not production code. Instead:
- After chunking works, capture behaviour as **characterisation tests** over the spike output where cheap: `test_spike_chunks_never_cross_headings` and `test_spike_section_paths_match_document_outline`, run against the two spike documents and their recorded chunk lists. Seeds for #7's real red-phase suite (and for #24's synthetic-fixture design), not gates.
- The committed findings note in `reviews/` is the primary artefact: each parsing failure mode observed (tables, figures, footnotes, two-column layouts) becomes a named test case in #7's TDD plan.
