## Context
DESIGN §3.7, ADR-020 as amended. The LLM writes a spec, never code; the vocabulary was validated against the flagship chart in #4.

## Scope
- JSON Schema for ChartSpec: chart types (line, area, bar, dual-axis line, context+recent-inset panel pair); transforms (resample, anomaly-vs-baseline, rolling-mean, unit conversion, `splice_series`, `time_axis` BP→CE, `rebaseline_to`); dataset ids from the pack; title/range/annotations.
- Pure-code validator: datasets exist, transforms legal, ranges sane, rebaseline periods match the manifest's allowed pairs, splice always paired with its annotation.
- Spec hashing for permalinks.

## Acceptance criteria
- `test_flagship_spec_validates` passes for the committed #4 spec; the invalid-spec suite (unknown dataset/transform/type, LLM-chosen alignment period, splice without annotation, out-of-coverage range) all rejected, with `test_rejection_messages_name_field_and_reason` proving the messages are actionable.
- Schema documented in-repo for the planner prompt (#16), kept in sync by `test_schema_doc_matches_schema`.

## TDD plan
Entirely pure code — the cleanest red–green issue in the plan (IMPLEMENTATION.md §1). All unit; order:
1. `test_flagship_spec_validates` — the committed #4 flagship spec passes: the vocabulary-covers-the-flagship regression.
2. `test_unknown_dataset_id_rejected`.
3. `test_unknown_transform_rejected` — anything outside the closed vocabulary.
4. `test_unknown_chart_type_rejected` — the five MVP types are a closed enum.
5. `test_splice_without_annotation_rejected` — `splice_series` without its rendered splice-point annotation + resolution note is invalid.
6. `test_rebaseline_period_not_in_manifest_rejected` — an LLM-chosen alignment period outside the dataset manifest's fixed pairs is invalid.
7. `test_splice_pair_not_in_manifest_rejected` — splicing datasets with no manifest-defined pairing is invalid.
8. `test_range_outside_dataset_coverage_rejected` — time ranges beyond the data are invalid.
9. `test_rejection_messages_name_field_and_reason` — every rejection is actionable (field path + why), asserted across the whole invalid-spec suite.
10. `test_spec_hash_stable_under_key_order` — canonicalised hashing: semantically identical specs hash identically; any semantic change changes the hash.
11. `test_schema_doc_matches_schema` — the in-repo schema doc for the planner prompt is generated from (or checked against) the actual schema, so they cannot drift.
