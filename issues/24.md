## Context
IMPLEMENTATION.md §4–5. Every LLM-dependent issue (#10, #12, #13, #16, #21) needs deterministic seams, and every ingestion/retrieval issue (#7, #9, #11) needs a corpus that is safe to commit. This issue builds both once, so no other issue improvises its own. Start it first in Phase 1 — it gates the red phase of most other issues.

## Scope
- `ProviderAdapter` protocol plus `FakeAdapter` (programmable responses; records every call) and `ReplayAdapter` (checked-in recorded response fixtures in `tests/fixtures/replay/`, keyed by canonical request hash; raises loudly on unrecorded requests, so a changed prompt invalidates its recordings by design).
- Recorder mode: env-flag-gated live recording, scrubbing API keys/headers from stored fixtures.
- Synthetic fixture corpus (`tests/fixtures/corpus/`): 4–6 fresh-authored documents (nested headings, a table, footnotes, calibrated-language sentences incl. a "not likely" negation trap, one `consensus_position: beyond-assessed-range` doc, one `source_type: voices` doc, one headline-statements doc), each carrying a `SYNTHETIC FIXTURE` first-line marker — never real Tier B/C text (DESIGN §2.1 shipping invariant). Plus a fixture manifest covering every `permitted_context` value with per-invariant violation entries, and tiny synthetic CSVs for chart-transform tests.
- Shared pytest conftest fixtures for adapter injection and fixture-corpus paths.

## Acceptance criteria
- `test_all_fixture_docs_carry_synthetic_marker` enforces that no unmarked (i.e. potentially real Tier B/C) text can sit in the fixture corpus.
- FakeAdapter and ReplayAdapter pass their own behaviour tests (TDD plan) and are consumed unmodified by at least one #10 test.
- Recording refuses to run without the explicit env flag and a live key; committed replay fixtures contain no secrets (`test_recorded_fixtures_scrubbed`).

## TDD plan
The infrastructure gets its own red–green cycle. All unit; order:
1. `test_fake_adapter_returns_programmed_response` — and exposes the recorded call list (method + full request payload).
2. `test_fake_adapter_supports_response_sequences` — sequential programmed responses, for retry-path tests (#16).
3. `test_replay_adapter_returns_recorded_response_for_matching_request` — canonical request-hash lookup.
4. `test_replay_adapter_raises_on_unrecorded_request` — loud failure naming the request hash and the re-record command.
5. `test_recorder_refuses_without_env_flag` — no accidental live calls from the test suite.
6. `test_recorded_fixtures_scrubbed` — no API keys or auth headers anywhere in committed fixture JSON.
7. `test_all_fixture_docs_carry_synthetic_marker` — first-line marker present in every corpus fixture document.
8. `test_fixture_manifest_covers_every_permitted_context` — `open`, `non-commercial-educational` and `permission-on-file` all represented, plus one violation entry per #5 invariant.
