## Context
DESIGN §9, ADR-015 as amended. The cap must never take the briefing fully offline.

## Scope
- FastAPI: SSE chat endpoint, chart permalink routes (#17), static pages.
- Hard daily spend cap tracked server-side; on breach, fail closed to **read-only**: pre-generated cached starter-topic answers + flagship charts (generated at release time, clearly dated), /about + source library + voices + permalinks still served; Opus behind a lower sub-cap.
- Per-IP rate limiting with hashed IPs (rotating salt, ≤7-day retention, never joined to query logs).
- Structured JSON logging per the privacy policy: 90-day retention job, eval-harvest review flow (hand-review + irreversible detachment), unsafe-content exclusion.
- Deploy: Docker Compose on Fly.io/Railway small VM (or equivalent) within the <£20/month target; ICO-registration check recorded before public launch.

## Acceptance criteria
- **GATE (DESIGN §10): cut-off verified to fail closed to the cached read-only state** — `test_breach_switches_to_read_only` (unit) plus `test_cutoff_fails_closed_end_to_end` (smoke, simulated breach against the composed stack).
- Rate limiter, retention jobs and log redaction covered by the named unit tests, including `test_logs_contain_no_raw_ips_or_identifiers` and `test_ip_hashes_deleted_after_7_days`.
- One-command deploy documented and executed to a staging URL.

## TDD plan
Budget, rate-limit, retention and redaction logic are pure with an injected clock; the fail-closed GATE gets both a unit state-machine test and a composed smoke test (IMPLEMENTATION.md §1, §3). Order:
1. `test_spend_tracker_accumulates_atomically` (unit, injected clock) — concurrent increments never lose spend.
2. `test_breach_switches_to_read_only` (unit) — crossing the cap flips the state machine to read-only, not to errors.
3. `test_read_only_serves_cached_answers_and_static_surfaces` (unit, test client) — starter-topic cache, /about, source library, voices and permalinks all serve; chat returns the dated paused response.
4. `test_no_llm_calls_in_paused_state` (unit, FakeAdapter) — zero adapter calls while paused.
5. `test_daily_reset_at_midnight` (unit, injected clock).
6. `test_opus_subcap_enforced_independently` (unit) — Opus blocked at its sub-cap while Haiku continues under the daily cap.
7. `test_ip_hash_uses_rotating_salt` (unit) — the same IP hashes differently across salt periods; raw IPs never stored.
8. `test_rate_limit_returns_429_over_threshold` (unit, test client).
9. `test_rate_limit_data_never_joined_to_query_logs` (unit) — log records carry no field linkable to the IP-hash store.
10. `test_logs_contain_no_raw_ips_or_identifiers` (unit) — log-capture scan over a simulated exchange.
11. `test_retention_job_deletes_over_90_days` and `test_ip_hashes_deleted_after_7_days` (unit, injected clock).
12. `test_unsafe_exchanges_never_enter_harvest_queue` (unit) — consumes #10's exclusion flag.
13. `test_chart_permalink_route_serves_stored_spec` (integration) — #17's route through the real service.
14. `test_cutoff_fails_closed_end_to_end` (smoke) — the GATE: composed stack, simulated breach, read-only behaviour verified from outside.
Deploy-to-staging and the ICO-registration check are process criteria with committed evidence (runbook + dated record), not tests.
