## Context
DESIGN §6.2–6.3 as amended. Evaluation is a first-class published deliverable; gates block release.

## Scope
- Deterministic metrics: Recall@8 / MRR / nDCG@8 vs gold chunk_ids; severity-retrieval recall on headline chunks; chart spec accuracy; chart data-faithfulness vs fixtures (stated tolerances); chart refusal; voices-separation structural check; calibrated-term regex proxy.
- LLM-judge metrics (judge ≠ generator, sampled human audit): faithfulness/entailment, confidence-level fidelity, **severity fidelity** (3-point ordinal vs gold annotation; gate ≥90% exact-or-adjacent, zero two-level errors), citation-support.
- Refusal metrics: >90% on the 20-item no-answer gate subset; false-refusal <5%.
- CI wiring: retrieval + smoke per PR; full suite per release/corpus version; results to `evals/RESULTS.md` (consumed by #19); A/B harness for pipeline changes.

## Acceptance criteria
- One command runs the full suite; deterministic metrics reproducible run-to-run; `test_release_build_exit_code_on_gate_violation` proves any gate violation fails the release build.
- RESULTS.md format pinned by `test_results_md_golden_format` and rendered on /about (#19).

## TDD plan
The harness's arithmetic is pure and fully unit-testable against synthetic run records with hand-computed expected values; judges run live per release only (IMPLEMENTATION.md §4.4). Order:
1. `test_recall_mrr_ndcg_hand_computed_values` (unit) — tiny synthetic run records with known-correct metric values.
2. `test_severity_agreement_exact_or_adjacent` (unit) — synthetic judge outputs → correct agreement percentage.
3. `test_severity_gate_fails_on_single_two_level_error` (unit) — one reassuring-vs-emergency disagreement blocks release regardless of aggregate score.
4. `test_chart_faithfulness_tolerances` (unit) — 1e-9 pass-through / 1e-6 post-transform applied correctly; a 2e-6 post-transform deviation fails.
5. `test_voices_separation_check_flags_violation` (unit) — a synthetic run with one voices chunk in a science query's document set fails the check.
6. `test_refusal_and_false_refusal_gates` (unit) — the >90% / <5% thresholds applied to synthetic outcomes.
7. `test_calibrated_term_proxy_negation` (unit) — "not likely" in an answer against "likely" in the source is not counted as preserved.
8. `test_judge_model_differs_from_generator` (unit) — config assertion; identical model ids fail.
9. `test_release_build_exit_code_on_gate_violation` (unit) — the harness exits non-zero when any gate fails, so release CI actually blocks.
10. `test_results_md_golden_format` (unit) — a synthetic run produces RESULTS.md matching a golden file (the /about contract with #19).
11. `test_full_suite_single_command` (integration) — one command runs the deterministic metrics end-to-end over the fixture corpus + gold subset.
The judge-based metrics (faithfulness, confidence-level and severity fidelity, citation-support, adversarial rubric incl. sceptic reception) run against the live model per release — they are the release gate, never a pytest tier.
