## Context
Everything else lands in this structure. DESIGN.md (header, §8) specifies a single public monorepo, Apache-2.0, Docker Compose, pytest CI.

## Scope
- Directory layout: `ingestion/`, `rag/`, `charts/`, `ui/`, `evals/`, `corpus/` (manifest only), `datasets/` (manifest + fetch scripts), `voices/`, `reviews/`, `scripts/`.
- Python 3.12 project setup (pyproject, lockfile, ruff, pre-commit).
- `docker-compose.yml` with `api`, `qdrant`, `ui` services (stubs fine).
- GitHub Actions: lint + pytest on every PR (eval jobs added later by #21).
- LICENSE (Apache-2.0), README stub with the project one-liner and non-affiliation disclaimer (DESIGN §4 item 11), CONTRIBUTING.md carried over.

## Acceptance criteria
- `docker compose up` starts stub services and each answers its health endpoint (`test_stub_healthchecks_respond`).
- CI green on a trivial PR; `integration`, `smoke`, `live` pytest markers registered and enforced with `--strict-markers`.
- README states the non-commercial public-benefit framing (DESIGN framing note) and links DESIGN.md / DECISIONS.md.

## TDD plan
This issue builds the harness the red–green cycle runs on, so its tests are meta-tests of the scaffolding itself (IMPLEMENTATION.md §2–3). Write first, in order:
1. `test_package_imports` (unit) — every top-level package (`ingestion`, `rag`, `charts`, `ui`, `evals`, `service`) imports cleanly.
2. `test_pytest_markers_registered` (unit) — `integration`, `smoke`, `live` markers registered in pyproject; unknown markers error under `--strict-markers`.
3. `test_compose_config_valid` (integration) — `docker compose config` parses and names the `api`, `qdrant`, `ui` services.
4. `test_stub_healthchecks_respond` (smoke) — `docker compose up` brings each stub service to a responding health endpoint.
CI wiring itself is verified by the trivial-PR acceptance criterion, not by a test.
