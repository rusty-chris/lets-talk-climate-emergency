## Context
DESIGN §3.2, ADR-005/007. Local bge-m3 producing dense + learned sparse vectors (NOT classical BM25), Qdrant with server-side RRF fusion.

## Scope
- Embedding job over #7's chunks: dense + sparse vectors, idempotent/incremental by content hash.
- Qdrant collection setup (Docker + embedded modes), hybrid query with RRF, top-40.
- Index versioning tied to corpus version.

## Acceptance criteria
- Full-corpus index builds on CPU with wall-clock time recorded in the build log; `test_full_reindex_idempotent` proves a no-change re-run embeds nothing.
- Hybrid query returns fused top-40 with chunk metadata intact.
- `test_known_query_hits_expected_fixture_document_family` passes at integration tier (deterministic, over the synthetic corpus).

## TDD plan
Incremental-embedding logic is pure with a stubbed `Embedder`; real models and Qdrant only at integration tier (IMPLEMENTATION.md §3). Order:
1. `test_unchanged_content_hash_skips_reembedding` (unit, stub embedder) — a second run over identical chunks embeds zero.
2. `test_changed_chunk_reembeds_only_that_chunk` (unit).
3. `test_index_version_records_corpus_version` (unit) — collection metadata carries the corpus version; a mismatch is detectable.
4. `test_dense_and_sparse_vectors_stored_per_chunk` (integration — Docker Qdrant + real bge-m3 over the fixture corpus).
5. `test_hybrid_query_returns_rrf_fused_top40_with_metadata` (integration) — fused results carry intact chunk metadata (section path, attribution, `source_type`).
6. `test_known_query_hits_expected_fixture_document_family` (integration) — the retrieval smoke check, written against the synthetic corpus so it is deterministic.
7. `test_full_reindex_idempotent` (integration) — rebuild with no changes re-embeds nothing and leaves the collection identical.
