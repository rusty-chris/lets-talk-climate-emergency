## Context
DESIGN §7.1–7.2. The front door for someone who has never had the briefing.

## Scope
- Landing page: name, tagline, and the four clickable starter-topic groups from §7.1 (tap → question asked immediately).
- Chat: streaming answers, citation chips with block highlighting, "unverified" badges (#13 contract), calibrated-term tooltips to the likelihood legend, "About the movement" styling on voices content.
- Retrieved-passages panel (desktop right, open by default; mobile "Sources (n)" sheet): verbatim bounded excerpts (Tier B always unadapted), attribution + deep links, cited-span highlighting.
- Source library drawer (doubles as the attribution surface).
- Inline charts with Download PNG/SVG · Copy permalink · View data & sources; alt text wired through.
- Accessibility: keyboard-navigable, semantic HTML, no information by colour alone.
- One-line logging disclosure in the chat UI (privacy contract, #22).

## Acceptance criteria
- `test_starter_questions_end_to_end` (smoke, replay-driven) passes; one live-pipeline pass recorded before release.
- The committed accessibility checklist (360 px layout, keyboard-only walkthrough, no colour-only information) completed and recorded per release.

## TDD plan
Streamlit files stay thin; every decision lives in `ui/presenters.py` and is unit-tested; browser-level checks are a committed manual checklist (IMPLEMENTATION.md §1). Order:
1. `test_starter_topics_match_design_list` (unit) — the four §7.1 groups and their exact questions, held as data, drive the landing page; drift from DESIGN fails.
2. `test_starter_topic_click_submits_question` (unit) — a topic click becomes an immediate query submission.
3. `test_citation_chip_mapping_from_answer` (unit) — `AnswerWithCitations` → chips mapped to the right passage blocks.
4. `test_unverified_badge_applied_on_validator_event` (unit) — #13's badge event flips the chip state post-stream.
5. `test_tier_b_excerpt_shown_unadapted_and_bounded` (unit) — passages-panel excerpts respect licence length bounds and are never adapted for ND sources.
6. `test_voices_content_flagged_about_the_movement` (unit) — voices chunks get the distinct styling flag; science chunks never do.
7. `test_calibrated_term_tooltip_targets` (unit) — calibrated vocabulary in an answer maps to likelihood-legend tooltip anchors.
8. `test_logging_disclosure_present_in_chat_ui` (unit) — the one-line disclosure is part of the rendered chat layout.
9. `test_starter_questions_end_to_end` (smoke) — all §7.1 questions run against the composed stack with the ReplayAdapter; charts render inline with download links.
10. Manual accessibility checklist, committed as evidence: 360 px walkthrough, keyboard-only navigation, no colour-only information — one recorded pass per release.
