## Context
DESIGN §3.3, §3.4, §5, ADR-008/012. The core answer path.

## Scope
- Thin provider adapter `generate(messages, documents, config) -> AnswerWithCitations`; Anthropic implementation with custom-content document blocks, `citations: {enabled: true}`, prompt caching on the static prefix; model id config (`claude-haiku-4-5` default, `claude-opus-4-8` behind the budget sub-cap).
- System prompt implementing the 8 rules of §3.3 — including rule 4 (lead with the headline finding at source severity) and rule 8 (`beyond-assessed-range` labelling).
- SSE streaming with citation events; enforce §3.4 constraints (no structured output on this call; all-or-none citations; top-8 documents only).
- Response footer (verification note + corpus vintage date).

## Acceptance criteria
- `test_live_cited_answer_end_to_end` (`live`-marked) streams a cited answer from the indexed corpus; runs per release and on demand, not per PR.
- The §3.4 contract tests pass: no structured output, ≤8 documents, no mixed cited/uncited blocks — each violation raising before any API call (FakeAdapter records zero calls).
- `test_cache_usage_logged` proves cache metadata from the response lands in the structured logs.

## TDD plan
The §3.4 contract tests are the heart of this issue — pure tests on the request builders, red before any Anthropic code exists (IMPLEMENTATION.md §4.3). Order:
1. `test_generation_request_never_sets_structured_output` (unit, contract).
2. `test_generation_request_rejects_more_than_8_documents` (unit, contract).
3. `test_generation_request_rejects_mixed_cited_uncited_blocks` (unit, contract) — every block must carry `citations: {enabled: true}`; a mixed set raises.
4. `test_constraint_violation_raises_before_api_call` (unit) — all three violations short-circuit pre-network (FakeAdapter transport records zero calls).
5. `test_system_prompt_contains_required_rules` (unit) — the assembled prompt contains the required elements of all 8 §3.3 rules (verbatim-qualifier, severity-lead, beyond-assessed-range attribution, voices labelling); a characterisation guard, not a quality claim.
6. `test_adapter_parses_recorded_response_into_answer_with_citations` (unit, ReplayAdapter) — recorded response shape → typed `AnswerWithCitations` with resolvable block references.
7. `test_streaming_citation_events_ordered` (unit, replayed SSE stream) — text and citation events emit in recorded order.
8. `test_model_id_comes_from_config` and `test_opus_requires_subcap_flag` (unit).
9. `test_footer_carries_verification_note_and_corpus_vintage` (unit).
10. `test_cache_usage_logged` (unit, replay fixture carrying cache-read metadata).
11. `test_live_cited_answer_end_to_end` (integration, `live`-marked) — one real query against the indexed corpus streams a cited answer; per release and on demand, never per PR.
